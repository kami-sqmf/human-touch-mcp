# Touch MCP 與 Human Input MCP 產品規格

本文件定義要實作的功能、操作規則與驗收要求，不代表功能已完成。

## 1. 分工與架構

- 官方 Touch MCP 保留官方原版完整功能，獨立安裝、啟動及更新。
- Human Input MCP 獨立提供擬人輸入、背景掃讀及倒數估算。
- Human Input 採 Node.js 工具層與獨立 Rust worker；透過具版本的本機 IPC 傳送計畫、進度、暫停、恢復與停止指令。
- Rust 使用 Windows API bindings 與 SendInput，負責原生輸入、視窗檢查、排程及按鍵狀態清理。
- 畫面內容、操作目的與頁面變更由外部觀察工具確認，再提供目標、座標及更新通知。
- 多個 Human Input 實例共用輸入鎖；衝突時拒絕，不排隊。使用官方 Touch 或其他工具輸入前，先停止 Human Input 工作。

## 2. Human Input 功能

| 功能 | 要求 |
|---|---|
| 滑鼠 | 提供移動、點擊、拖曳及捲動，使用自然曲線、速度變化與適度回修。 |
| 逐字輸入 | 可調整速度與節奏；預設不製造錯字，另外啟用時才模擬錯字及修正。 |
| 按鍵 | 提供編輯、導覽、Enter 與 Ctrl 組合鍵；每次呼叫執行一個明確操作。 |
| 系統剪貼簿 | 沿用 Windows 的複製、剪下與貼上功能，由系統與接收程式處理內容。剪下、貼上必須使用獨立明確呼叫，不能藏在一般按鍵呼叫或打字流程中。 |
| 背景掃讀 | 接受多個有順序、目的、方向與時間預算的區域，立即回傳工作識別，在背景自主移動游標。 |
| 倒數估算 | 接受外部讀取的倒數，以單調時鐘估算；分開回報觀察值、估計值、資料年齡與不確定範圍。 |
| 工作控制 | 提供模式開關、狀態、進度、暫停、恢復、停止及待處理事件查詢。新程序預設關閉輸入模式。 |

背景掃讀只包含純移動與有目的的停留。其他輸入逐次呼叫、確認結果後再決定下一步。查詢狀態、進度與倒數不得打斷掃讀；新輸入、停止、目標或模式變更，須先取消原掃讀並確認停止。

## 3. 目標視窗與輸入檢查

- 使用視窗代碼、程序身分及建立時間識別目標；座標採實體螢幕像素，處理多螢幕與 DPI 差異。
- 輸入前及執行期間檢查目標身分、前景、可見性、遮擋、位置、大小、DPI 與游標；鍵盤輸入另外檢查焦點及鍵盤狀態。
- 目標不在前景時，允許單獨點擊呼叫者指定的安全區域。先確認最新位置、可見且未被遮擋；呼叫者須確認該區域不會更改內容、導航或提交。
- 安全區域點擊後回報結果，重新確認前景與座標，再接受後續輸入。無法確認安全時拒絕點擊。
- 畫面內容改變、座標失效或輸入結果不明時，要求外部重新觀察。

## 4. 暫停、接管判定與恢復

### 游標異常

1. 偵測到非預期游標移動時，立即暫停當前工作與後續輸入，保存執行進度。
2. 在最多 3 秒的觀察期間記錄游標位置與時間，以移動持續性、累積路徑及活動範圍判斷；不能只因暫停滿 3 秒就認定接管。
3. 持續且大範圍的移動一旦符合條件，就維持暫停並立即通知 Agent，不必等滿 3 秒。
4. 短暫小幅移動結束後，重新檢查目標、前景、游標及工作狀態。符合恢復條件時，自動接續原工作；仍不穩定或無法判斷時保持暫停。
5. 接管成立後，由 Agent 重新檢查並明確要求恢復。回報使用「工具偵測到游標接管」，不推定操作者或誤報原因。

移動、穩定時間與判定門檻須可調整，並以實測校正。軌跡紀錄限於暫停判定所需的有界資料，回報保留原因、時間、進度與必要軌跡摘要。

### 接續規則

- 所有工作都可在條件符合時恢復；區分已送出、尚未送出及結果不明的部分，只接續尚未執行部分。
- 點擊、拖曳、打字、捲動與剪貼簿操作各自定義可恢復的進度點；不能把整個動作重新播放。
- 暫停時妥善釋放本工具按住的按鍵與按鈕。若釋放已改變動作語意，例如中斷拖曳，須先確認接收端狀態，再決定如何接續。
- 若無法確認操作是否已生效、焦點是否仍正確或內容是否改變，保持暫停，交由 Agent 檢查。
- 恢復時依目前游標重新規劃剩餘路徑，重新計算剩餘時間；不瞬移回舊位置，也不快速補送過期事件。
- 視窗異常與輸入失敗須暫停並回報原因，不套用游標接管的 3 秒判定。明確停止、模式關閉、斷線及程序重啟後，不自動恢復。

### 即時通知

- 提供接管與異常事件，包含工作識別、原因、時間及已完成進度。
- 驗證客戶端能將事件即時交給 Agent，包含 Agent 正在思考時的情境；事件送出與 Agent 收到必須分開記錄。
- 若客戶端未提供所需接收能力，明確回報不支援，保留待處理事件並維持暫停，不宣稱已即時通知。

## 5. 倒數與執行限制

- 外部觀察前後建立時間範圍，將讀取及傳輸延遲納入倒數估算；校正時回報新舊差值。
- 頁面切換、暫停、恢復或觀察超齡時，使舊錨點失效並要求重新校正。一般有效期限為 60 秒，最後 30 秒內為 10 秒。
- 區分未知、有效估算、超齡、已觀察暫停、估計到期及已觀察結束。估計歸零不得觸發輸入。
- 各種操作須設定時間、事件數及資料量上限；排程延遲過大時停止或暫停，不快速補送。
- 取消完成後不得再送出新輸入；已送入 Windows 的事件不能撤銷。清理未確認時禁止接續新工作。

## 6. 必須避免的行為

- 強制呼叫焦點切換 API，或擅自移動、縮放、最小化及重排目標視窗。
- 以系統快捷鍵切換視窗，或繞過安全區域點擊的檢查。
- 預排多個點擊、拖曳、捲動、鍵盤或剪貼簿操作，讓失敗後的動作繼續執行。
- 將逐字輸入暗中改成貼上，或重複執行已完成的動作。
- 釋放使用者原本按住的按鍵，或強制終止尚未完成輸入清理的 worker。
- 將輸入事件送出當成接收端操作成功，將游標移動當成已完成閱讀，或將推估倒數當成畫面實讀。
- 在更新或部署時未經要求改寫現用 MCP 設定。

## 7. 安裝、更新與移機

- 交付 Windows x64 可攜式資料夾，包含 Node.js、預編譯 Rust worker、所需套件、啟動器與授權文件，盡量解壓即可使用。
- 官方 Touch 與 Human Input 分開存放與註冊；執行相依完整，啟動前檢查無法內附的系統需求。
- 啟動路徑以套件位置解析。搬移到其他電腦後，重新產生符合當地路徑的 MCP 設定，不沿用舊電腦的絕對路徑。
- 提供安裝、啟動檢查、設定產生、更新、回退及版本查詢指令。
- 只有執行更新指令才檢查及下載新版。兩個 MCP 可分別更新，記錄來源、版本與校驗資訊。
- Human Input 接受本機新版套件或明確指定的 HTTPS 下載網址，驗證預期雜湊後才安裝；官方 Touch 從官方來源取得。
- 更新先停止工作，下載至新版本目錄，完成完整性與啟動驗證後才切換；失敗保留原版，成功後仍保留可回退版本。

## 8. 開發與驗收

- 先固定工具、IPC、工作狀態與恢復進度契約，再分工實作 Node.js、Rust、規劃器與封裝；由獨立子代理審查整合結果。
- 驗證單次輸入、背景掃讀、唯讀不中斷、新輸入取消、執行進度、短暫移動自動恢復及持續大範圍移動通知。
- 驗證操作中途暫停不會重複點擊、輸入、剪下或貼上；不明結果會維持暫停。
- 驗證焦點、遮擋、幾何、DPI、鍵盤狀態、斷線、輸入鎖與清理失敗。
- 使用專用可見測試視窗核對實際接收結果，並驗證即時通知、可攜式安裝、更新失敗與版本回退。
- 驗收報告分開列出通過、失敗及略過項目；單次略過不改變後續驗收要求。
