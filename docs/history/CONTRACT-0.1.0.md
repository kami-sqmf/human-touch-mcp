## Node↔Rust line-delimited JSON, protocol 1

Requests: `{id: integer, command: string, ...fields}`. Responses exactly one per request: `{id, ok:true, result:object}` or `{id,ok:false,error:{code,message}}`. No unsolicited stdout; diagnostics stderr. 2 MiB maximum line, bounded state. Rust rejects malformed/unknown commands safely. Node may have multiple in-flight requests; worker's command reader must remain responsive while an operation runs. Every command carries id; no SDK or JSON-RPC inside worker. `hello` result `{protocol:1,version:'0.1.0',platform:'windows',capabilities:{...}}`. `ping` result `{alive:true}`. Ping/other commands renew 3s local parent lease; Node sends ping every 500ms. Lease loss or stdin EOF cancels; this is NOT a chat heartbeat.

`observe {hwnd:string}` -> `{snapshot_id, target_id, hwnd, identity:string, rect:{x,y,width,height}, client:{x,y,width,height}, cursor:{x,y}, foreground:string, focus:string, dpi:number, ready:boolean, observed_at:string}`. HWND decimal >0; identity PID+process start. Store recent 32 snapshots; reject start snapshot older than 5000 ms. Observation is read-only; never cancels by itself. It does not assert anything about page contents. Pure Rust snapshot checks without images. Node uses returned snapshot_id for start.

`start {operation_id:string, snapshot_id:string, kind:'move'|'click'|'drag'|'typing'|'reading', duration_ms:number, events:Event[], threshold_px?:number=60, force_ime_off?:boolean=false}` -> `{operation_id,state:'running'}` promptly. Independent native execution validates baseline and starts. No queue: already live => input_busy. Terminal failure after async acceptance recorded in status. IDs cannot be reused in retained records. Validate full plan before any input. Frames monotonically nondecreasing at_ms 0..duration_ms. <=12000 events. kind max durations: 15000ms mouse,45000 typing,60000 reading. threshold_px configurable 10..500, default60. Reject empty/invalid/unbounded plans and invalid kind/event combinations. Snapshots bind identity/geometry/dpi/foreground and typing focus at actual execution. Require same initial cursor (within threshold) to avoid overwriting takeover between observe and start.

Event: `{type:'move',x:number,y:number,at_ms:number}`; `{type:'button_down'|'button_up',at_ms:number}` (left only); `{type:'char',text:oneUnicodeCodepoint,at_ms:number}`; `{type:'backspace',at_ms:number}`. Reading/move only move; click has one down/up balanced pair after moves; drag one pair with moves while held; typing char/backspace only. No public arbitrary key chords or Enter. ASCII use physical scan codes based on target keyboard layout, preserve Caps Lock/modifiers. Printable nonASCII may use Unicode packet; no promised remote delivery. Each char is pulse with ~35ms hold, backspace40ms; release own modifiers on all normal cancellation/error paths. Reject control chars, held user modifiers/buttons at start rather than releasing user's input. Reject IME on unless force_ime_off explicit; restore only for same target identity. Don't paste.

Runtime guard before each injection and during waits (bounded <=20ms): same foreground/identity/rect/dpi, visible/enabled/unminimized; focused child unchanged for typing; cursor deviation from last actual own injection <=threshold. Check unoccluded client hit/point owner at mouse points, no chrome. Use virtual-desktop absolute SendInput + readback. A failure stops, no retry fallback. Post-injection readback mismatch fails; don't silently set expected=actual when divergent. Do not infer physical user provenance. Report code pointer_takeover/message 'Tool detected pointer takeover'. No image/page check. Access restriction/UIPI produces error. In-flight OS events can't be revoked.

`status {operation_id}` -> `{operation_id,state:'running'|'completed'|'cancelling'|'cancelled'|'failed',elapsed_ms:number,injected_events:number,reason?:string,error?:{code,message},inputInjected:boolean,deliveryVerified:false}`. Retain at most32 terminal operations, never evict running. No cancellations on queries. `cancel {operation_id?:string, reason?:string}` -> `{state:'idle'}` if no work or full terminal status. Set cancellation immediately, wait barrier max2s; only return cancelled once no future injections possible. Failed/finished remains its state; idempotent. Timeout => cancellation_timeout, poison/block new work until cleanup proven. Stopping/cancel never queues behind a whole operation. Release only owned input; no cursor return.

Cross-process lock: same interactive Windows desktop Human workers use named Local\\HumanInputMCP.Input.v1 mutex acquired/released on execution thread, conflict => input_owner_conflict. Does NOT constrain Touch/other software. Startup owns no lock. Don't install Windows Service.

## Pure planning interface (agent C)

`lib/planners.mjs` exports sync `planMove({from,to,durationMs?,jitterPx?,overshootPx?,bounds?,gesture?}) -> {durationMs,points:[{x,y,atMs}],algorithm}` (use existing ghost-cursor code as licensed baseline; clamp all points within explicit bounds).
`planTyping({text,wpm=41,typoRate=.006,seed?}) -> {events:[{type:'char',char,atMs}|{type:'key',key:'backspace',atMs}],durationMs,targetWpm,characterCount,seed,effectiveTypoRate,algorithm}`. No Python. <=1000 codepoints, no controls/unpaired surrogate. duration=codepoints*12000/wpm <=45000; 15<=wpm<=180;0<=typoRate<=.3. Variable timing/word-group pauses including corrections within total. Typo corrections ASCII only; replay must exactly match text. Same explicit seed deterministic. Count hold overhead35ms UTF16 unit for nonASCII or 35 ASCII,40 backspace; reject impossible plan. `replayTyping(events)` and `inside(point,rect)` exported.
`planReading({from,segments,bounds}) -> {durationMs,points,algorithm}` <=60000; each segment `{region_id,rect,purpose,direction:'top_to_bottom'|'left_to_right',duration_ms}`; rectangles inside target client, purpose nonempty. Only points, no down/up/keys. Purposeful traversals plus dwell, no pointless jitter; last planned time cannot exceed budget. Validate all input first.

`lib/timer.mjs` exports class `TimerStore` optional constructor `{now:()=>performance.now(), wallNow:()=>Date.now()}`; methods attach({target_id,section_id,timer_id?}), prepare({timer_id}) -> observation ticket, calibrate({timer_id,ticket_id,observed_seconds,state?:'running'|'paused_observed'|'expired_observed'}), status({timer_id}), invalidate({timer_id,reason?}), detach({timer_id}). Receipt of external observation bracketed by prepare ticket and calibrate: use monotonic uncertainty interval, no invented exact capture time. Return observed input separately from estimated integer seconds/range; stale 60s or10s last30; drift difference when new anchor; observed expiry needs explicit state. unknown/stale estimate=null; expired_estimated cannot claim observed. Bounded tickets/timers. Pure timer never touches worker/cancels reading.

## Node service interface (agent B)

MCP stdio server low-level SDK; tools human_capabilities,human_mode,human_observe,human_target_update,human_input_plan,human_mouse_move/click/drag,human_type,human_stop,reading_start/status/cancel,timer_attach/prepare/calibrate/status/invalidate/detach. Strict JSON schema. Per input supply explicit hwnd and fresh observation OR Node calls worker observe immediately; fresh external page knowledge remains caller responsibility. Target update cancels barrier before replacing target. No auto focus. Do not let status queries cancel background.
Use `HumanService` exported in lib/service.mjs with constructor `{worker, planners?, timers?}` and async `call(name,args,signal?)` testable without SDK; worker `.request(command,fields?)`. `lib/worker-client.mjs` WorkerClient starts configured HUMAN_INPUT_WORKER or relative bin/human-input-worker.exe then native/target/release/... (no PATH injection); `.request`, `.close`; kill/EOF invalidates all outstanding requests, no auto restart; hello protocol validated, ping unref'd. cancel is priority semantically (reader independent, no serial await queue). On errors close resources.
Mode flips invalidate pending accepted work/generation; mode off cancels active. Normal inputs serialized admission with busy rejection, not queued; incoming input cancels reading then validates mode/generation again before start. NEW reading busy refuses unless replace=true then cancels; status readonly. Sync move/click/drag/type call start then await status terminal; AbortSignal cancels barrier. reading_start returns immediately. Max history32 service maps. HTTP/network listener not needed.
